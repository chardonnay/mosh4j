= mosh4j 2.0.2

This release focuses on *security hardening* of the transport and datagram layers, a verified *upstream-MOSH protocol review*, expanded *automated testing* (including interoperability against the real C `mosh-server`), and AsciiDoc documentation with rendered Mermaid diagrams — all since `v2.0.1`.

== Highlights

* *Security hardening* (see link:../security_best_practices_report.md[Security Best Practices Report])
** *Dependency (H-1):* Bouncy Castle `bcprov-jdk18on` upgraded `1.78.1` → `1.84`, fixing CVE-2026-5598 (HIGH) and CVE-2026-0636 (MODERATE).
** *Replay / freshness protection (M-1):* new per-direction `ReplayWindow` (sliding window) drops duplicate and stale datagrams before any state-mutating processing — AEAD prevents forgery but not replay of captured ciphertexts. `TransportReceiver` now runs side-effecting diffs only for genuinely advancing states, so retransmissions no longer double-apply terminal output. On the server the replay check runs before the roaming address is updated.
** *Decompression-bomb limits (M-2):* `FragmentCodec` caps reassembled/zlib-decompressed output at 16 MiB and bounds buffered fragment bytes; `TransportInstruction.parse` enforces a size limit.
** *Protocol-version check (L-1):* `MoshServerSession` now validates `protocol_version` on inbound instructions, symmetric with the client.
** *Supply chain (L-2, L-3):* GitHub Actions pinned to full commit SHAs; root POM adds `<pluginManagement>` plus `maven-enforcer-plugin` (enforces JDK 21 / Maven 3.8+); new OSV-Scanner CI workflow and Dependabot configuration.
* *Upstream MOSH review*
** Verified directly against upstream `mobile-shell/mosh`: the wire protocol is still version `2` and the latest release is `1.4.0`, so Mosh4J is already wire-compatible and *no protocol migration was required*. Recent upstream `master` changes (OSC 8 hyperlinks, `getrandom`/`getentropy` PRNG, signal handling, NaCl drop) are terminal-layer or C-runtime concerns and do not affect the wire format. See link:upstream-mosh-review-2026-06.adoc[Upstream MOSH Review].
* *Testing*
** New unit tests: `ReplayWindow`, `FragmentCodec` (decompression limit), `TransportReceiver` (freshness guard), and `TransportInstruction` (protocol-version + size guard).
** New live UDP loopback integration test (`MoshLoopbackRoundtripTest`): real sockets, host-output delivery, and replay/freshness drops end-to-end.
** New real-server interop test (`MoshRealServerInteropTest`): spawns the genuine C `mosh-server`, connects the Mosh4J client over UDP with the server-provided key, and verifies the client decodes real mosh wire traffic. Self-skips when `mosh-server` is not installed (CI-safe).
* *Documentation & diagrams*
** Documentation moved to AsciiDoc; README and the Java Integration Guide were overhauled.
** Mermaid diagram sources added under `docs/diagrams/` with `docs/generate-diagrams.sh`; rendered PNGs committed for GitHub display.
** The protocol-stack diagram now shows the receive-side anti-replay / freshness check.

== Changes since v2.0.1

== Modules

[cols="1,2"]
|===
| Module | Description
| `mosh4j-protocol` | Protobuf definitions and generated DTOs (transport, user input, host input)
| `mosh4j-crypto` | AES-128-OCB, nonce/seq handling, Mosh key decoding (Base64)
| `mosh4j-transport` | SSP transport (instructions, state window, acks, fragmentation)
| `mosh4j-terminal` | Terminal state (framebuffer, minimal ANSI parser)
| `mosh4j-core` | Client and server session APIs, UDP datagram layer, anti-replay window
|===

== Requirements

* *JDK 21* (LTS)

== Usage

* *Build:* `mvn clean package`
* *Tests:* `mvn test` (the real-server interop test self-skips unless `mosh-server` is installed)
* *Test server:* `./scripts/run-mosh4j-server.sh [port]` – prints `MOSH CONNECT <port> <key-redacted>` (set `MOSH_PRINT_KEY=1` to show the key) for client connections

Use `MoshClientSession` or `MoshServerSession` from `mosh4j-core` with a UDP port and session key (e.g. from `ssh user@host mosh-server` or from the test server output).

See also: link:java-integration-guide.adoc[Java Integration Guide]
